## CodeBuddy 授权状态不更新（修复）
- 现象：应用内发起 CodeBuddy 授权、浏览器登录完成后，设置页授权状态一直「未授权」。
- 根因（src/codebuddy-cli.js）：
  1. 凭据文件名写死 `Tencent-Cloud.coding-copilot.info`，本机实际凭据是 `%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\workbuddy-desktop.info`（文件名规律 = <客户端产品名>.info，各客户端一份）。
  2. 旧兜底扫描用 `/coding-copilot/i` 过滤，同样漏掉新文件。
  3. `workbuddy-desktop.info` 的 accessToken/nickname 是 WorkBuddy 桌面端加密信封对象（`{$wbEncrypted:1, envelope}`），expiresAt/refreshExpiresAt 为明文——token 字符串检查也把它排除。
- 修复：新增 `discoverCredentialFile()` 扫描目录下全部 `*.info` 择优（未过期 > expiresAt 大 > mtime 新）；`hasCredentialToken()` 同时接受明文与加密信封 token；`plainText()` 净化加密 nickname；`readCredentialRaw()` 合并源改读择优文件。写入路径保持旧固定名不变（不碰其他客户端的文件）。
- 验证：credentialState 现返回 installed/authenticated=true、stale=false、有效期至 2026-11-20。
- 遗留：云端拉取依赖 CLI serve 能否使用加密凭据，未实测；若失败走应用内授权写明文文件兜底。UI 授权轮询在离开设置页时会被 useEffect cleanup 终止（SettingsView.tsx:69-75），登录期间勿切页。

## CLI 按需下载方案实现（端到端验证通过）
- 架构：安装包不再内置 CodeBuddy CLI（pack-backend.js 移除 copyCliTree，载荷约 -50MB）；CI 每平台构建分发件 `.pkg.gz` + 元数据 json 挂 Release；设置页显式触发下载（镜像回退）→ sha256 校验 → 流式解压到 `~/.agentsessions/cli/node_modules/`；resolveEntry 优先级 bundled > user。
- 新文件：`scripts/cli-pkg.js`（依赖树复制 + 自研 pkg.gz 格式 [magic 9B][pathLen u32][mode u32][size u32][path][data]，零新依赖）、`scripts/build-cli-pkg.js`（CI 入口）、`src/cli-installer.js`（下载/校验/解压/标记，进度态机）。
- 改动：pack-backend.js（移除 CLI 打包）、codebuddy-cli.js（resolveEntry 加 user 回退 + userCliRoot 与 AGENT_SESSIONS_CLI_DIR 对齐）、server.js（status 扩展 installState + POST /api/codebuddy/cli/install）、api.ts/SettingsView.tsx（两态按钮 + 进度轮询）、build.yml（三平台构建分发件上传 Release）、.gitignore（dist-cli/、.tmp-test-cli/）。
- **解压器关键 bug**：header 相位解析完后 buf 余量未回流导致单 chunk 场景只落 1 个文件、大文件场景永久挂死——重构为单一 pending 缓冲状态机修复。小样本（空文件/中文文件名/二进制）与真包（10390 文件/13.7s）均通过。
- **路径约定坑**：copyCliTree 产出扁平布局（resolvePkg 根级 cand 多拼一层 node_modules，靠 fallback 兜住），pkg 内路径统一剥离 node_modules/ 前缀，安装器直接解压进 cliRoot/node_modules/。
- **本机环境干扰（非产品 bug）**：WorkBuddy 注入 NODE_OPTIONS shim（safe-delete 劫持 rmSync→genie-trash、bulk-guard 对批量写文件限流致解压假死）+ CODEBUDDY_GATEWAY_AUTH/PASSWORD 环境变量（优先级高于 --auth none，致 serve 401）。测试须 `NODE_OPTIONS= ` 且 unset 这两个变量。
- 验证结果：bundled 优先 → 屏蔽后回退 user v2.170.0 → serve 就绪回收；tsc --noEmit 通过。
- 遗留：`.tmp-test-cli/`（221MB 测试残留）被环境 safe-delete 锁死无法删除，已 gitignore，需会话结束/重启后手动删；CI 三平台构建未实测（等下次发版触发）。

## manifestRepo 收紧为 https-only
- 背景：讨论远端清单 external 限制时确认信任链弱点——httpGet 原允许 http:// 且跟随重定向，官方仓库走明文链路即可被替换清单内容（external = 唯一 RCE 面）。
- 改动：src/manifest.js httpGet 协议校验改为仅 https（错误文案同步），移除未再使用的 node:http require；readme.md 两处（manifestRepo 配置说明、远端拉取失败排查）更新为 https；SettingsView.tsx 设置页提示改为「填入 https 仓库 URL（仅支持 https）」。
- 未动：远端 external 禁令维持（用户/内置清单不受限），本地目录为 external 逃生口。
